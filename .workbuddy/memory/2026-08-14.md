## 实现：Personal Decision Council v0.2 全栈

基于 `Personal_Decision_Council_v0.2_架构迭代总结.md` 落地了"先问后答"的个人决策议会。

### 后端（backend/）
- Python + FastAPI + SQLite（零核心依赖，核心逻辑仅用标准库）
- LLM 抽象：MockLLM（确定性，供自测）/ DeepSeekLLM（urllib 调用 OpenAI 兼容接口，无需 requests）
- 议会状态机：INIT → WAITING_ANSWERS → COUNCIL(5 角色顺序发言) → CROSS_EXAM → MODERATOR → (CLARIFICATION) → COMPLETED
- 5 角色：理解者/支持者/反方/现实主义者/战略顾问 + Moderator；角色可 SKIP；动态 Problem Context

### 前端（frontend/）
- uni-app (Vue3 + Vite)，一套代码打 Android/iOS/H5
- 聊天式 UI，渲染 role_questions/agent/cross_exam/moderator/action_plan/clarification

- 已对齐官方模板版本，README 已记录。

## Bug 修复：配置 DeepSeek key 后仍走 Mock

用户反馈"key 已配置但仍是 mock"。根因有两点：
1. **`.env` 从未被读取**：原 `config.py` 只 `os.getenv`，无加载 `.env` 的逻辑（也无 python-dotenv），用户按 `.env.example` 填的 key 被完全忽略。
2. **`LLM_PROVIDER` 默认 `mock`**：必须显式设为 `deepseek` 才用真实模型，用户多半只填了 key。

修复（`backend/app/config.py`）：
- 新增 `_load_dotenv()`：启动时加载 `backend/.env`（与 cwd `.env`），仅填充未存在的变量（真实环境变量优先级更高），不引入新依赖。
- provider 改为自动识别：`LLM_PROVIDER` 留空时，有 key → deepseek，无 key → mock；仅显式 `mock` 才强制 mock。
- `.env.example` 默认 `LLM_PROVIDER=` 留空；README 增加 `/api/health` 验证与"清掉系统环境变量 LLM_PROVIDER"提示。
- 验证：`tests/_verify_env.py` 4 场景通过（已删除）；`test_council_mock.py` 8 项、`test_server_mock.py` 集成均 PASS。
